Case Study: Subnet Migration & Routing Recovery

Status: Resolved

Scenario

A planned migration of the local LAN from 192.168.1.0/24 to 192.168.137.0/24 resulted in a cascade of DNS resolution failures, asymmetric routing drops, and severed management access to the OPNsense Web GUI.

Root Cause Analysis

  • DNS Access Control: Unbound DNS strictly dropped requests from the new unrecognized subnet because ACLs were not automatically reloaded.
  • State Tables: Outbound NAT rules failed to automatically regenerate for the newly established logical network boundaries.
  • DHCP Lease Conflicts: Downstream Wi-Fi 7 APs and switching hardware maintained stale gateway IP leases, triggering DHCP resolution failures.

Resolution & Hardening

Used the OPNsense CLI to execute a configuration rollback, restoring management access. Manually flushed DNS ACLs and rebuilt Outbound NAT tables via the root shell. To prevent future gateway drops during reboots, the LAN interface was explicitly pinned to a Static IPv4 configuration in config.xml, and downstream networking equipment was factory-reset to force clean IP allocations from the updated Kea DHCP pool.
