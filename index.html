VLAN & Subnet Architecture

Segment Subnet Gateway DHCP Pool Purpose
LAN (Untagged) 192.168.1.0/24 .1 .200 - .250 Switch management and fallback access
VLAN 10 (TRUSTED) 192.168.10.0/24 .1 .130 - .250 Wi-Fi 7 AP and trusted personal wireless devices
VLAN 20 (SERVERS) 192.168.20.0/24 .1 .200 - .250 Hypervisor, LXC containers, and SIEM VM
VLAN 30 (IOT) 192.168.30.0/24 .1 .100 - .250 Untrusted IoT segment (staged, rules disabled)
VLAN 40 (WORKSTATIONS) 192.168.40.0/24 .1 .100 - .250 Primary wired desktop workstations
Overlay (Tailscale) 100.64.0.0/10 Firewall CGNAT Encrypted mesh for remote access

Subnetting Scheme

  • One /24 per VLAN: mask 255.255.255.0, 254 usable hosts, with the third octet matching the VLAN ID.
  • Gateway Convention: the firewall owns .1 on every segment.
  • Address Plan: static infrastructure and DHCP reservations sit below the dynamic pool.
  • Trunking: one 802.1Q trunk carries all tagged VLANs between firewall and switch.
  • Overlay Separation: Tailscale uses CGNAT space, apart from the RFC 1918 ranges.

DHCP & DNS Design

  • Kea DHCP: per-VLAN pools plus reservations for known devices.
  • Unbound DNS: access lists default to refuse, with an explicit allow per segment.
  • DNS Interception: hardcoded DNS clients are redirected to Unbound through destination NAT.
  • Upstream Privacy: queries leave using DNS-over-TLS with certificate verification.
  • Filtering: ad and privacy blocklists refresh hourly.

Inter-VLAN Access Policy

DNS Bypass Prevention

  • Blocked Protocols: DNS-over-TLS, DNS-over-QUIC, and DNS-over-HTTPS to known resolver lists.
  • Exceptions: a small allow alias for sites broken by the blocklist.
  • Outbound Plain DNS: rejected so only encrypted upstream queries leave.

Intrusion Prevention

  • Suricata IPS: Netmap mode across all seven interfaces with Hyperscan pattern matching.
  • Signatures: rules update nightly; firmware updates run automatically.
  • Log Hygiene: short retention keeps IPS logs from filling storage.

Zero-Trust Remote Access

  • Tailscale ACLs: tag-based rules permit only the flows each device needs.
  • Tailnet Lock: new nodes need a signature from one of two signing nodes.
  • Account Hardening: manual user approval, 30-minute sessions, and 180-day key expiry.

Layered Firewalls

  • Layer 1: OPNsense stateful rules between every VLAN.
  • Layer 2: Proxmox datacenter and node firewalls with a final drop rule.
  • Layer 3: per-container rules that admit only the intended upstream service.

Internal Certificate Authority

  • Private PKI: an internal root CA on OPNsense issues HTTPS certificates for the firewall, Proxmox, Vaultwarden, Nextcloud, and Gitea.
  • Hidden Hostnames: no public CA means no Certificate Transparency entries or public DNS A records for internal names.
  • Trust Model: only my own devices and servers trust the root certificate, and Unbound resolves the names locally.

INC-01 | October 4, 2026

LAN Re-Addressing on a Live Firewall

Status: Resolved & Verified | Impact: GUI lockout, AP lease failure, DNS refusals

Objective

Re-address the firewall LAN subnet and DHCP range as a planned change, with the AP, DNS, and hypervisor following.

Impact

  • Web GUI became unreachable after the interface change.
  • The AP stopped receiving leases and fell back to 169.254.x.x.
  • Unbound began refusing queries and NAT state fell out of sync.
  • The Proxmox host was stranded on its old static address.

Resolution

  1. Restored the config backup from the physical console, then re-applied the interface IP and DHCP range.
  2. Reloaded Unbound and the packet filter from a root shell, then rebooted to clear stale state.
  3. Factory-reset the Wi-Fi 7 router and reconfigured it in Access Point Mode.
  4. Re-addressed the Proxmox host from its console and the containers through the web UI.

Takeaways

Take a config backup and confirm console access before touching a management subnet, and update dependents (AP, DNS access lists, static hosts) in the same change window.

INC-02 | October 29, 2026

Zero-Trust VLAN Segmentation

Status: Resolved & Verified | Impact: link-local clients, stalled overlay access

Objective

Split the flat LAN into role-based segments: a /24 per VLAN, an 802.1Q trunk to the switch, and default-deny between zones.

Issue 1: Link-Local Addresses on Workstations

Clients on tagged VLANs fell back to 169.254.x.x. Fixed by disabling hardware VLAN filtering on the firewall NIC driver.

Issue 2: Stalled Remote Access to Servers

Overlay clients hit asymmetric routing when reaching VLAN 20. Replaced the legacy LAN hairpin rule with outbound NAT on the SERVERS interface (source: overlay network, destination: SERVERS network, translated to the SERVERS gateway address) so return traffic stays symmetric.

Outcome

Five verified segments with scoped inter-VLAN rules, per-VLAN DHCP pools, and overlay access that works from outside the network.
